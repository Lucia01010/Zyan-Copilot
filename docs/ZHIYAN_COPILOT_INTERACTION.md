# 知妍·伴答交互设计（M16）

## Host 与 Plugin

左侧客户列表和中间聊天属于模拟千牛 Host，表达“消费者 ↔ 客服”。右侧知妍·伴答属于独立 Copilot，表达“客服 ↔ 知妍”。插件通过 `PluginContext` 获得当前 `session_id`、客户和消息，不直接操作 Host 内部状态；复制建议回复仍通过 Host Action 写入回复编辑器。

## 右侧信息结构

插件只保留四个客服工作区：

1. **客户洞察**：当前诉求、情绪、风险和一句话摘要。
2. **知妍建议行动**：最多 1–4 个经过 Registry allowlist 的真实按钮。
3. **知妍 Agent**：客服可以点击 Action 或自由提问；每条结果展示简洁结论和数据来源，不展示 raw JSON/tool trace。
4. **知妍生成建议回复**：基于当前会话、业务查询结果和风险判断，可复制到 Host 回复框。

内部 tool calling 仍存在，但不再以“知妍工作流”和“信息核查”大卡片长期占据插件空间。

## Quick Action 生命周期

`客户会话 → 建议行动 → 点击按钮 → session_id 绑定的 Business Tool → SQLite 实例数据 → Agent Chat 结果 → 建议回复更新`。

自由提问走同一边界：事实型问题必须先选择 Registry 中的可执行工具。找不到记录时输出缺失信息，不猜测。

## 会话隔离

插件切换会话时清空 Agent Chat、重新拉取建议行动；每次执行请求都携带当前 `session_id`。因此客户 A 的物流或工单结果不会复用到客户 B。

## 数据与比赛说明

“真实查询”指当前比赛提供并导入 SQLite 的实例数据，不代表连接淘宝生产系统。未来如获得资质，只需替换 Host Adapter/数据适配器；当前 Agent、风险看板和插件交互不需要改变。
