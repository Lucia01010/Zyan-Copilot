# 售后规则

> 适用范围：退换货、退款、打款、物流异常、补换货与不良反应等售后政策类问题的统一回答口径。本文档是通用政策说明，不能用于回答某个具体订单/工单的实时状态；具体订单状态必须通过业务工具查询。

## 七天无理由退货条件

退货条件与规则：

1. 顾客自签收商品之日起 7 天内可申请无理由退货，商品需保持未使用、未拆封或不影响二次销售的状态。
2. 以下情况不适用无理由退货：已明显使用的彩妆与护肤品、赠品已单独使用、顾客人为损坏的商品。
3. 礼盒、套装按整套退货，不支持拆套退其中单品。
4. 预售商品的退货时效同样自实际签收之日起计算。

## 退货退款处理流程

标准退货退款流程：

1. 顾客提交退货申请并说明退货原因（return_reason）。
2. 客服核实后引导顾客寄回，登记退货物流单号（return_tracking_number）与承运商。
3. 仓库签收并验收商品无误后，创建退款编号（refund_number）并发起退款。
4. 退款按原支付路径退回，一般 1-3 个工作日到账，具体以支付渠道处理时效为准。

注意：退款是否已实际到账属于订单事实，不能凭政策推断，必须通过退款/打款查询工具核实后再答复顾客。

## 退款与线下打款规则

1. 原路退回适用于线上支付订单；超过线上退款时效或特殊场景（refund_issue_type 登记的情形）走线下打款。
2. 线下打款通过支付宝或银行卡处理，需要登记收款实名信息与账号、退款金额（refund_amount_yuan），并核对转账状态（transfer_status）。
3. 客服只能按工单登记的信息核对打款进度，不得在聊天中复述完整支付宝账号或银行卡号，注意顾客隐私保护。
4. 打款进度以 offline_payment_work_orders 工单的转账状态为准，不能向顾客承诺具体到账时点。

## 物流异常处理规则

1. 常见物流异常包括：未收到货、物流轨迹长期停滞、显示签收但顾客未收到、破损等，对应 issue_type 在物流工单中登记。
2. 处理步骤：先核对订单承运商与物流单号（problem_tracking_number），再向承运商核查轨迹；停滞或签收异常需建物流工单跟进。
3. 客服不得凭顾客口头描述直接承诺补发或退款，需以承运商核查结果与仓库记录为准。
4. 物流问题导致的补发/退款，在物流工单 resolution 确认后按对应流程处理。

## 补换货规则

1. 适用场景：漏发、少件、错发、商品破损或质量问题，登记 replacement_work_orders 工单。
2. 顾客需提供包裹与商品照片作为凭证，客服核对订单商品（sent_product_sku/sent_product_name）与数量后登记补发或换货。
3. 补发商品有独立补发单号（replacement_tracking_number）与承运商，由履约仓库（fulfillment_warehouse）发出。
4. 催办标记（complaint_urgent）为紧急的工单优先处理，承诺的补发时间要与仓库确认后再告知顾客。

## 不良反应特殊处理通道

1. 顾客反馈使用产品后出现发红、瘙痒、刺痛、起疹等疑似不良反应时，第一原则是建议顾客立即停用并用清水清洗，症状明显或持续时建议及时就医。
2. 客服必须登记不良反应工单（adverse_reaction_work_orders），记录：使用产品与批号（used_product / product_batch_number）、症状描述（symptom_description）、使用部位、出现时间（onset_after_use）、是否已停用（stopped_use）、是否就医（sought_medical_care）。
3. 疑似不良反应属于高优先级事项，应主动安抚情绪并升级处理，不得轻描淡写或要求顾客继续使用观察。
4. 是否需要退换货或补偿，以不良反应工单处理结论为准，客服不得自行承诺赔偿方案。

## 售后通用时效与承诺规则

1. 常规售后咨询应在当次会话内响应；需要跨部门核实的事项，应告知顾客预计跟进时间并按承诺回访。
2. 所有时效类答复（如"今天内""24 小时内""明天"）必须先与对应工单或仓库确认可以达成，再对顾客承诺。
3. 售后单关闭不代表款项必然到账，顾客询问时以退款/打款工单状态为准并做好解释。
4. 政策没有覆盖的特殊情形，统一升级主管处理，不得自行解释或拒绝顾客。
