# 知妍 AI（Zhiyan Beauty Copilot）验收标准

## 自动验收门槛

### 官方允许的验证方式

- [ ] 采用 React/Vibe Coding 模拟客服工作台，或场景数据模拟 + Agent 结果展示 + 插件 Demo 交互。
- [ ] 不以真实千牛生产部署、真实店铺、商家账号或开放平台权限作为比赛完成条件。

- [ ] 原始比赛材料未被修改；解析和生成物与 `data/raw/` 分离。
- [ ] `docs/PROJECT_STATE.md` 存在并记录架构、数据导入、启动命令、测试结果、模型配置、token 成本和已知限制。
- [ ] 干净环境可初始化 SQLite，重复导入不会产生重复核心记录。
- [ ] 后端可启动；`GET /health` 成功；核心 API 对空数据、无效 ID 和正常数据有明确响应。
- [ ] 后端测试覆盖 schema/导入、至少一个业务 Tool、规则风险、mock Agent 和关键 API。
- [ ] 前端可启动并能访问 `/workbench` 与 `/risk-dashboard`，具备加载、空态、错误态，且不依赖真实 Qwen。
- [ ] `/workbench` 展示上下文、建议回复、风险提示，并支持编辑或人工接管动作。
- [ ] `/risk-dashboard` 支持风险列表、等级/状态筛选、详情证据和跟踪状态更新。
- [ ] Qwen 使用环境变量和 OpenAI-compatible endpoint；日志/提交物无密钥；mock 与 remote 路径有清晰标识。
- [ ] 风险结果包含来源、证据和建议动作；模型失败不会吞掉规则结果。
- [ ] 有 token/耗时统计和可复现的评估命令或测试输出。未运行测试和 smoke test 不得报告完成。

## M9–M11 路线与完成定义

### M9 — Product / Demo Polish

- [ ] `/workbench` 与 `/risk-dashboard` 的关键交互、空态、错误态、视觉层级和演示路径稳定。
- [ ] 主要业务事实、风险证据、人工接管和状态跟踪在演示中可解释。

### M10 — Competition Demo Packaging

M10 是默认比赛交付终点，必须不依赖真实千牛生产权限完成以下闭环：

- [ ] 可模拟消费者咨询并选择真实赛题会话/场景。
- [ ] 可模拟人工客服工作台操作。
- [ ] 右侧 Agent 插件展示意图、情绪、证据、订单/工单、时间线、风险、建议动作和建议回复。
- [ ] Agent 或规则命中的风险事件写入风险看板。
- [ ] 风险看板支持状态跟踪和更新。
- [ ] 至少有一组稳定、可重复的演示场景。
- [ ] 有一键启动或最少步骤启动方案。
- [ ] 有演示说明，明确 mock/真实 Qwen 状态、数据来源和已知限制。
- [ ] 后端、前端、相关测试和 smoke test 实际运行通过。

### M11 — Simulated Qianniu Plugin Runtime

- [ ] `/workbench` 明确呈现模拟千牛客服工作台宿主与知妍·伴答插件两个边界。
- [ ] 存在 Host → Plugin `PluginContext` 和 Plugin → Host `PluginActions` 合约。
- [ ] 会话切换、新消息、分析开始/完成、风险创建事件不会污染其他会话。
- [ ] Scenario Controller 支持固定 A/B/C 真实案例快捷入口和重新加载；不得用虚构客户或预设消息替换真实会话。
- [ ] 智能回复建议通过插件 action 写入宿主 Reply Composer。
- [ ] 插件可打开 Risk Dashboard，风险事件、证据、服务轨迹和状态形成闭环。
- [ ] `docs/PLUGIN_RUNTIME.md` 完成；离线测试、typecheck、build 和浏览器闭环通过。

### M12 — Optional Real Qianniu Integration

- [ ] 仅在用户明确要求，并具备真实店铺、商家账号、开放平台权限和必要资质时进入。
- [ ] 缺少上述条件时，M11 标记为未启动，不得阻塞 M10 或比赛项目完成。

## 演示路径

1. 启动后端和前端，打开 `/workbench`。
2. 选择一个源数据客户/会话样例，查看订单和商品上下文。
3. 生成建议回复，确认风险提示、证据和人工接管入口可见。
4. 打开 `/risk-dashboard`，筛选高风险，查看详情并更新状态/备注。
5. 查看健康检查与成本统计，说明使用 mock 还是远程 Qwen。

## 质量与安全底线

- 涉及过敏、不良反应、投诉升级等场景应建议人工确认，不输出医疗诊断或确定性合规结论。
- 不记录 API key、完整敏感会话或无必要个人信息；演示数据尽量脱敏。
- 测试必须命中真实 service/API 路径，不用静态 JSON 或截图伪造结果。
- 外部 endpoint 或依赖失败时保留可运行 mock 闭环，并在状态文档明确阻塞点。
- [ ] 真实千牛接入属于可选增强，不得把未部署到生产环境误报为项目失败，也不得把模拟工作台冒充生产插件。

## Token 成本记录

每次 Agent 运行记录时间、模型/provider、输入/输出 token（若 endpoint 提供）、工具调用数、延迟和成功/失败。按会话或评估批次聚合，注明估算与实测的区别；不要为统计重复发送同一 Prompt。
